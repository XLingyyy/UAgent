# 暂停后补充要求与重新规划（2026-11-06）

后台文件调查现支持在用户暂停后补充要求，保存后再继续。此能力限定于当前进程内的单成员只读任务；不扩展读/分享范围、不增加模型或工具额度、不延长任务期限，不恢复历史授权。通用写任务、完整步骤编辑和指定步骤跳过仍待实现。

## 当前行为

- 补充要求最多 2048 个 UTF-16 单元，最多修订 3 次；每次替换此前的补充要求，初始目标保留。使用界面观察到的计划版本进行核对，旧版本提交被拒绝。
- 已完成的工具结果保持原样。模型已经提出但尚未执行的调用收到明确的 `cancelled / not_started / user_replanned` 结果，数据库动作状态为 `skipped`。没有调用执行器，也没有伪造成功结果。
- 原 assistant 工具请求和消息前缀不修改；追加对应的工具结果、用户补充要求与检查点。计划版本递增。保存后仍保持暂停，点击继续才重新请求模型。
- 上下文选择保留初始目标，强制包含最新补充要求；旧补充要求标为 superseded，完整历史仍保留。预算不足时拒绝继续，不静默丢弃最新要求。后续发送照常检查来源和原生授权。
- 保存失败不会确认修订成功。未保存的状态不能绕过后续持久化检查开始新请求。
