# T10 bounded multi-file build repair

Independent runtime coordinator `packages/runtime/src/ue-build-repair.ts`; native `ue_build_repair.rs`, `ue_build_repair_io.rs` and their local tests. It reuses the existing MVP12 SHA-256/text-backed diff helpers and T09 build/diagnostic contracts. No shared model, global router, Tauri command, Provider transport, approval UI or production UE permission is changed. The existing path-based `text_mutation.rs` is not presented as handle-bound I/O.

## Finite contract

A host fixes project/root object, host-session generation, run, profile fingerprint and 1–8 explicitly readable existing Source files. This slice accepts `.cpp`, `.h`, `.hpp`, `.Build.cs`; no new files, deletion, moves, `.Target.cs`, project descriptors, Config, binaries or assets. Text is UTF-8 without NUL; each before/after is at most 256 KiB, combined preview text at most 1 MiB. Scope/path aliases and duplicates fail closed. Extending scope requires new host authority.

The coordinator consumes an actual owned T09 execution result, parses diagnostics with trusted native roots/cwd, reads native hash/object-bound snapshots, and asks a proposer for closed `{files:[{path,after}]}` data. Default two repair attempts, hard maximum three. Every attempt needs a new exact native apply approval and a separate native build approval. Only confirmed failed, stopped builds with complete usable diagnostics allow another attempt. Cancel, stale scope, conflict, partial/unknown writes, incomplete logs and uncertain process termination stop the loop. Final failure retains the latest preview, per-file effects, logs reference and history; it never silently discards edits.

`createFixtureBuildRepairProposer` and the unit fixtures exercise model-shaped input without a model/API. They are not real model repair acceptance. A preview ID, plan digest, TS object, diagnostic ID or file hash cannot authorize execution.

## Native operations and lifetime

`RepairSession::from_verified_host` accepts a live `TrustedRootHandle` plus trusted binding/diagnostic context and exact allowed files. Its constructors are native-only, not authority deserialized from tool JSON. The host must first resolve the actual saved build owner/result; frontend diagnostic references are correlation data, not proof of an owned failure.

1. `read_snapshots` reads through the held-root reader. While each data handle is still open, it acquires a metadata-only file-object pin and verifies the same identity. Snapshot and prepared-plan pins retain that object through approval and later snapshots; they allow normal user edits so conflicts remain observable.
2. `prepare_preview` compares exact current snapshot content/hash/object ID, scope, binding and diagnostic; it computes a separate native digest. UI must review the native-registered full plan. `NativeRepairGrant::from_verified_host_approval` recomputes the DTO digest before accepting it, uses monotonic expiry, supports revocation and one-use consumption. It does not implement a UI or mint permission from model input.
3. `apply_approved` opens **every** existing target relative to its held parent, with no sharing, before the first source write. It compares the old identity pin, new handle identity and full original hash. A conflict in file two prevents a write to file one. Only after preflight and final checks is the grant consumed and a full before bundle flushed through `RepairJournal`. `DirectoryRepairJournal` exclusively creates a new record in a separately host-owned directory; existing records are never overwritten.
4. Files are overwritten and read back through those same owned handles. Cancellation, approval revocation/expiry and root state are checked between bounded file operations. Results distinguish applied/not-started/partial/unknown/conflict and retain a recovery-record reference. This is not a multi-file transaction; an interrupted write can have unknown effects. There is no forced thread termination or automatic rollback.
5. `hold_applied_inputs_for_build` resolves the native registered applied receipt and obtains read handles for all changed files, verifies actual after hash/object identity, and retains them through T09 execution. Outside changes block this verification; ordinary writes/replacement fail while the guards are held. These guards bind only this changeset, not the whole project or engine, and do not approve a build.
6. `query_recovery` reads actual target hashes/IDs without writing. `prepare_restore` makes a **new** preview only for known-applied files still matching their recorded after state; it requires a new grant. Outside edits and unknown writes require manual reconciliation. Backups survive as data, not reusable approval/session authority. Process restart recovery is not automatically adopted.

The only held-root API addition is crate-private `PinnedDirectory::borrow_verified_handle`: a checked borrowed directory object for native adapters, not a write grant. No raw handle/root is returned through IPC. The native host must still maintain the current run/root lease and serialize project/build resources. Root/current checks and byte limits do not prove that every namespace TOCTOU or power-loss case is eliminated; synchronous file flushes are not interruptible midway. See [root migration limits](trusted-root-handle.md).

## Main integration ports

`BuildRepairNativePorts` is the exact runtime boundary; implementations must come from the protected host, never from model callbacks.

| Port | Minimal protected host implementation |
| --- | --- |
| `assertActive` | Check actual registry generation, root object identity, project/run/profile, expiry and cancellation. Invalidate/revoke old mappings on change. |
| `readSnapshots` | Resolve the owned failed build by owner, bind its diagnostic correlation, create/lookup a native session and call its held-root snapshot reader for the exact requested scope. |
| `applyWithNativeApproval` | Project the TS preview to `RepairPreviewInput`: retain binding/diagnostic/snapshotId/previewId and path/before/after/hashes/object ID; strip schemaVersion/repairId/attempt and display diff fields. Save previewId → native plan digest in the native registry, review that actual plan, issue/consume the native grant, and execute on a blocking worker. |
| `buildWithNativeApproval` | Request includes `{binding,owner,appliedPreviewId,expectedSources:[{path,sha256,objectIdentity}]}` derived from validated applied effects. Compare it with the original native preview/receipt, obtain and retain `hold_applied_inputs_for_build`, obtain independent exact build approval, then use T09 prepare/execute/cancellation. Pass `owner` unchanged; do not relabel a previous result. Recheck guards at dispatch and keep them until the owned process tree settles. Source conflict returns an honest not-started result; it is not another automatic repair attempt. |
| `queryRecovery` | Resolve the native registered preview, query its original targets only; a supplied path list cannot widen scope. This does not establish that a previously unknown build stopped. Query that exact owner through T09 separately. |

Native apply receipts also contain `recoveryRecord`; retain it in the host journal/preview mapping. Runtime's closed receipt projection adds the actual UI decision and omits this extra field; **do not discard the native recovery record** merely to satisfy the transport schema. Query receipts map directly after exact context validation. Native plan digest is not required to equal the TS correlation hash.

Persist intent/backup/receipt and checkpoint through the existing run store; do not serialize grants, file handles or live leases. Handle callbacks lost after dispatch as unknown effects. Propagate AbortSignal to the exact native cancellation owner/flag and wait/query for real completion; aborting an await does not prove rollback or process shutdown. Never broaden v1 MCP permissions or enable Lab writers as part of this integration. Log/source sharing with a Provider still needs the existing outbound consent policy.

## Verification and evidence

Local runners are `scripts/test-ue-build-repair.mjs` and `scripts/test-ue-build-repair-native.ps1`, after the E/G environment helper. Runtime: **65/65** deterministic tests, focused type/lint/format checks. Native: **13/13** real Windows filesystem tests, covering two-file writes/backup, all-file preflight conflicts, cancellation/revocation between files, separate approved restoration, outside edits, DTO digest tampering, metadata-pin lifetime and held build after-state. The native runner filters out the unchanged 14 root tests; it does not launch UE or run the desktop suite.

Real UE 5.8.2 / CL 56702186 acceptance is confined to the existing isolated `UAgentBuildLab`. `Evidence/t10_missing_http_final` records T09 UBT exit **6**, LNK2019 for `FHttpModule::Get` and LNK1120, caused by missing `HTTP` in the module's Build.cs. `Evidence/t10-native-http-repair-final` records the final native snapshot → exact preview → separate explicit test approval → durable backup → approved existing-file apply → held changed-source inputs → actual T09 UBT exit **0**, stopped owned tree and complete output. Only Win64 Development Editor was built; no Editor/PIE or network request was started. The compile probe merely references the module symbol and is never invoked. Existing asset hashes remain separately recorded.

The initial include-only probe succeeded because the installed Editor target exposed the header transitively; a subsequent incorrect probe API caused C2039. Those attempts are retained and explicitly excluded from missing-module acceptance. Final acceptance uses the corrected installed API and actual unresolved import, with before/after source hashes and copied real UBT logs. Native test approvals are not production user UI approval. The real Lab harness calls native apply/T09 directly; the global TS → protected IPC → native application route and a real model repair remain unverified and unenabled.
