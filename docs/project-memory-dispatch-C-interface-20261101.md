## Proposed native command wrappers (central decides/registers; absent = closed)

All wrappers are strict deny_unknown_fields DTOs, schemaVersion 1. Input IDs are correlation only; native window ownership, SAME run/request/lease/grant/root/approval/batch Arcs and current generations are independently checked. No scope, read/share prefix, renderer permission, grant or permit is accepted.

Owner descriptor: {runHandle, runId, projectId, projectEpoch, providerId, modelId}. This wraps B's receipt; it is never added to B's serialized batch or used to reconstruct a grant. projectEpoch is the original native owner epoch, not a renderer counter. Project/root/window barriers still require native implementation, including ABA and late registration.

- prepare_native_project_memory_selection input {schemaVersion,runHandle,selected:[{id,revision}]}; reply {schemaVersion,owner,expiresAt,batch:<B receipt>}.
- prepare_native_responses_request MEMORY EXTENSION input {schemaVersion,runHandle,body,memoryBatchId}; reply {schemaVersion,owner,expiresAt,batchId,requestId,endpoint,body,bodySha256}. The reply body is the full immutable native original body, byte-identical to submitted final body. It is retained natively with B's BoundMemoryRequest. C rejects the old/non-memory reply shape. Existing non-memory callers retain their old path.
- approve_native_responses_request MEMORY EXTENSION input {schemaVersion,runHandle,requestId,memoryBatchId,bodySha256}; reply action='approved' below. Approval exists only inside native. This reply does not expose it. Central must call this only after the real gate reviewed the full exact body; no fake/mock gate or renderer boolean authorizes the native read/share grant.
- dispatch_native_responses_request MEMORY EXTENSION same input; reply action='scheduled' below. This is the SAME existing request sender, not a second memory transport. Central replaces the one existing dispatch IPC with this companion call; it must not call both or fall back. Calling this schedules work only, not proof of transport or first-byte delivery. Poll/stream consumption remains with the existing native Responses session and its original requestId.
- cancel_native_project_memory_dispatch input {schemaVersion,runHandle,batchId:null|string,requestId:null|string}; reply action='cancelled' below. Native resolves the original owned run and permanently cancels/discards all its current memory preparations even when a lost prepare/select reply left IDs unknown. It never waits for vault/SQL. It acknowledges only after native request/session revocation, never by trusting the renderer. The operation is bounded and single-shot from C. It does NOT delete persistent data or close another run.

Select and prepare may alternatively return the SAME strict terminal rejected action reply: select echoes batchId=null/requestId=null; prepare echoes the original batchId/requestId=null. Native must permanently discard the failed preparation before returning that proof; C never filters/refetches a partial selection. Action reply: {schemaVersion,owner,batchId:null|string,requestId:null|string,action:'approved'|'scheduled'|'cancelled'|'rejected',dispatchStatus:'notDispatched'|'mayHaveBeenSent'|'sent',terminal:boolean,reason:null|'stale'|'replay'|'cancelled'|'expired'|'contextChanged'|'unavailable'|'invalid'|'cleanupFailed'}. Approved is nonterminal/notDispatched; scheduled is nonterminal/mayHaveBeenSent; rejected is terminal with a reason; cancellation is terminal. A terminal notDispatched reply is accepted only from the exact original native operation, after all future dispatch for that request is impossible. No thrown/raw IPC text is treated as zero-send proof. Missing/malformed/lost action replies are outcomeUnknown. No retry is automatic and the same companion cannot be reused after any dispatched/failed/invalidation attempt.

## C validation and lifetime

The contract keeps B's <=256 selection, <=64 total sources, <=8 sources/member, <=8192 body bytes, <=24576 original context and <=1048576 full raw-body bytes, all using UTF-8. It checks selected order/IDs/revisions against the exact canonical member list, file_preview only (freshness absent or exactly equal to the original version, retaining the field unchanged), complete metadata and paths. All raw JSON keys are unique, including escaped duplicates; depth is bounded. Wire input[2] must be the exact B message after system/developer, <=30 items, canonical serialized input within the original context limit, and exactly one native memory marker in the decoded document. Neither JSON reserialization nor substring-only binding is accepted as authority. JS never creates a new canonical segment or rebuilds the approved full body.

Bridge captures the original renderer lifecycle identity object and native owner descriptor only to notice invalidation; these are not native grants. It checks both before and after asynchronous work, listens to AbortSignal, arms native expiry, and supports explicit contextChanged()/close(). Cancellation starts without awaiting a pending select/prepare/dispatch. An internal invalidation race immediately ends local IPC/hash waiting; late replies cannot restore the state. Native cancellation acknowledgement is bounded to 2000 ms; a lost/late acknowledgement remains outcomeUnknown and is never retried. A->B->A with a new lifecycle object is rejected even if strings match. Native R2 must independently prevent ABA when UI callbacks miss an event. Dispatch is attempted at most once, transitions conservatively to mayHaveBeenSent before IPC, and never automatically retries on rejected/lost/malformed acknowledgements. A successful cancellation may refine to notDispatched only with the exact terminal native proof. OutcomeUnknown never becomes approved again.
