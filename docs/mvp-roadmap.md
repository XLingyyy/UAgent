# UAgent Product Roadmap

UAgent combines a desktop conversation workspace with policy-controlled Unreal Engine tooling. This roadmap reflects r14 and the unreleased build-repair slice, including real desktop acceptance on 2026-11-06 (America/Phoenix). The first build-repair changes were pushed to GitHub in `da9e071`; no new version has been released. See [README](../README.md), the [current T01–T24 status](next-phase-current-status-20261030.md), and [r14 acceptance](releases/r14.md) for implementation and verification boundaries.

## Next delivery order

1. Complete ordinary-project interactive Blueprint creation, supported graph changes and visible behavior verification.
2. Complete ordinary-project scene loading and the 20-object / interrupt-after-seven continuation acceptance.
3. Complete general execution tasks, independent runtime hosting, UI resubscription and general task / UE-object restart recovery.
4. Complete data summaries and active-provider project memory, backup/export and migration, dynamic/mixed-model collaboration, then Windows first-use/install/upgrade/Beta acceptance.

Build-repair follow-up still needs a separate existing C++ game project for related-source changes and runtime behavior. Long-source rejection and a successful smaller scope under the 32 KiB request / 1024 output-token limits remain unverified. Desktop partial restoration after restart, other crash windows and power-loss recovery remain outside the accepted scope; see [failure-recovery evidence](build-repair-failure-recovery-20261106.md). Native pointer drag/double-click and Windows Snap checks also remain open.

The original Responses/Anthropic milestones are a recorded route difference, not completed active-provider deliverables. Current capabilities retain explicit outbound review, native operation approvals, trusted-root containment and separation of saved history from new execution authority. The two model-assisted Lab cases cover one changed file per request. The Test01 results cover manual-draft and model-assisted two-file batches in a newly added controlled module. The three-round manual-draft acceptance establishes stop behavior after repeated build failures; it does not establish three model-generated repair rounds or a successful final build. Historical restoration of a fully applied write after a failed rebuild has also passed across a real application restart; the restoration finished with controlled compile errors in the source and included no rebuild. Normal native-build cancellation and a timing-instrumented partial-write/same-session restore have passed within their recorded limits. Existing game source, runtime behavior, broader crash/power-loss recovery and Windows Beta acceptance remain open. Existing module tests and historical Lab runs cover their recorded versions and scopes; the remaining real acceptance work is listed above.
