# UAgent Product Roadmap

UAgent combines a desktop conversation workspace with policy-controlled Unreal Engine tooling. This roadmap reflects r14 and the unreleased build-repair slice, including real desktop acceptance on 2026-11-06 (America/Phoenix). The first build-repair changes were pushed to GitHub in `da9e071`; no new version has been released. See [README](../README.md), the [current T01–T24 status](next-phase-current-status-20261030.md), and [r14 acceptance](releases/r14.md) for implementation and verification boundaries.

| Area | Implementation boundary |
| --- | --- |
| Desktop | Tauri/React workspace, task composer, project sidebar, optional tool drawer, settings, Chinese/English localization, and incremental conversation rendering. |
| Provider | DeepSeek API and official Codex app-server are active. Responses and Anthropic implementations are archived. Saved DeepSeek credentials use Windows Credential Manager; their native session supports discussion only. |
| Runtime and collaboration | Bounded read-only investigation, pause/resume/cancel, shared budgets, independent members and synthesis are connected. Ordinary Codex conversation and two-member investigation passed real r14 acceptance; dynamic delegation and mixed-provider combinations still need real acceptance. |
| History and memory | SQLite records, session search/rename/archive/branch/continue, and local fact/decision/todo management are connected. Current active providers do not have the approved project-memory dispatch formerly attached to Responses. |
| Projects and UE reads | Trusted-root file/index tools, loaded Blueprint structure and direct asset-reference queries are connected. Codex investigation currently exposes only list/find/read file tools. |
| Build repair | Fixed-target builds, up to eight-file source repair, reviewed online suggestions and local imports are connected. Two real desktop/DeepSeek repairs passed in an isolated UE 5.8.4 Lab: C2065 and missing HTTP dependency, each with two input files, one changed file and an approved successful rebuild at 1/3. A newly added controlled C++ module in a copy of the user's empty Blueprint project Test01 passed both manual-draft and real DeepSeek two-file repair chains, with native writes applied and separately approved rebuilds at exit 0. The model proposal changed one line each in `.cpp` and `.h`; the chain used one request after the temporary key was corrected and 1/3 rebuilds. The original Test01 had no Source and no files in Content and was left unchanged. The earlier generic failures remain untraceable. A separate manual-draft run with no model calls passed the three-rebuild limit: diagnostics fell 4 → 3 → 2 → 1, the third rebuild still exited 6, and the UI stopped without a fourth rebuild. The 32 KiB request, 1024 output-token and three-approved-rebuild limits remain. A live external edit to the second file after preview also rejected the entire write batch: cpp stayed `not_started`, the header was `conflict`, both byte checks passed, and no backup, restore candidate or rebuild was created. The native repair test entry was repaired and passed 24 tests. See [current evidence and limits](next-phase-current-status-20261030.md). |
| Blueprint and scenes | The pickup creation/compile/save workflow remains limited to the isolated Lab. Scene contract 2.4.0 supports 1–20 reviewed Engine-shape objects in a new map in an ordinary trusted project, with same-run query/resume/save. The plugin has compiled on UE 5.8.4; current load and behavior acceptance remain open. |
| Host and recovery | An application-level Rust host and shared resource queue are connected. Eligible settled source repairs have a newly approved inverse-restore path after restart. History-event reading and completed-write recovery admission received narrow fixes: 19 frontend tests plus integrated type checking, and nine native process/SQLite tests passed. The updated web/native builds exited 0, and write/build history details with attachment entry points passed real desktop read-only checks after reopening the same profile. After re-trusting the Test01 copy and verifying the original process had ended, real desktop restoration of a fully applied write after its failed rebuild passed: one cpp line was reversed under fresh approval, LF and the header were preserved, and no rebuild or model call followed. Live partial-write/cancellation recovery remains unverified. The independent TypeScript sidecar, general task continuation and UE object recovery across restart remain incomplete. |

## Remaining product work

- General execution tasks, editable plans, step skipping, mid-task requirements and the optional task-scoped continuous authorization mode from the design.
- Source-linked long-history summaries, project memory in active model tasks, richer source/Blueprint relationship queries, and user-facing capacity/backup/export controls.
- Extend the accepted controlled two-file model repair to existing game source in an independent project copy and verify runtime behavior. Extend the accepted historical restoration of a fully applied write after a failed rebuild to live partial-write/cancellation recovery, and verify remaining failure paths and request/output-limit rejection; retain explicit approvals at each step. The three-rebuild stop boundary has passed with manual drafts and a final failed build.
- Complete the other original UE workflows on the current desktop/engine: an interactive Blueprint in a supported project, and 20 scene objects with interruption after seven and verified continuation.
- Independent runtime hosting, UI resubscription, general restart continuation, cross-process resource exclusion and current external-effect verification.
- Real dynamic/mixed-model collaboration acceptance and comparison with a single agent; remaining real API error, usage and long-session checks.
- Native pointer drag/double-click and Windows Snap verification on supported systems.
- First-use flow completion, distributable Windows installers, declared signing status, manual upgrade/data-migration checks and Beta acceptance on a clean Windows environment.

The original Responses/Anthropic milestones are a recorded route difference, not completed active-provider deliverables. Current capabilities retain explicit outbound review, native operation approvals, trusted-root containment and separation of saved history from new execution authority. The two model-assisted Lab cases cover one changed file per request. The Test01 results cover manual-draft and model-assisted two-file batches in a newly added controlled module. The three-round manual-draft acceptance establishes stop behavior after repeated build failures; it does not establish three model-generated repair rounds or a successful final build. Historical restoration of a fully applied write after a failed rebuild has also passed across a real application restart; the restoration finished with controlled compile errors in the source and included no rebuild. Existing game source, runtime behavior, live partial-write/cancellation recovery and Windows Beta acceptance remain open. Existing module tests and historical Lab runs cover their recorded versions and scopes; the remaining real acceptance work is listed above.
